求职篇 02 · 面试知识图谱

十二个必考主题：一句话回答 + 追问链

每个主题给你“面试版一句话”和面试官最可能的追问链。回答的底气全部来自教程落点——追问到第几层，取决于你把那份源码读到第几层。

面试知识图谱（追问链按深度排列）
主题面试版一句话高频追问链教程落点
Agent LoopAgent 是“模型请求→工具调用→结果回填→再请求”的循环，不是一次 API 调用；turn 的终止条件是本轮没有工具调用。怎么防死循环？→ 工具结果坏了怎么办？→ stopReason=length 为什么标记错误？第 03 课、高级篇 J.3/J.5
上下文工程上下文是每次请求的稀缺租期，按系统提示词/工具声明/历史/工具结果/输出预留五块分开管理。哪块最大？→ 怎么持续审计？→ 压缩怎么工作？高级篇 G.2、进阶篇 C.3
提示词缓存缓存按前缀命中，系统提示词一个字符变化就打穿；静态放前缀，每请求变化的放消息尾部。怎么证明？→ 隐藏成本有哪些？第 05 课踩坑、高级篇 H.3
长对话自动压缩在下一轮请求前触发，摘要是有损的，关键约束要放每次都完整加载的位置。切分点为什么不能落在工具结果上？→ 摘要失败了怎么办？进阶篇 C.3/C.4
工具安全模型提议、我的代码执行；参数校验在扩展钩子之前，硬上限必须在 execute 里再查一次。拦截和观察的区别？→ 被拦截的调用有什么事件？→ 审计怎么绕坑？第 07 课、高级篇 J.5/H.1
流式输出delta 只管渲染，end 才负责正确；落库计费以 message_end 为准。并行工具调用事件交错怎么配对？→ 客户端断开呢？高级篇 K.1/K.2、实战篇 02
并发与排队同一会话同时只有一个 run；忙时要么排队要么插话，必须显式选，SDK 拒绝替你猜。“看起来空闲其实忙”的窗口？→ 409 和排队怎么选？第 02 课踩坑、高级篇 J.1、生产篇 6.2
评测四层金字塔：工具单测→会话集成→提示词回归→全链路冒烟；提示词、工具描述、模型版本任一变更必须重跑。怎么过 CI 门禁？→ 非确定性怎么压？高级篇 H.4
成本治理三笔隐藏的钱（压缩摘要、缓存预热、失败重试）+ 模型分级 + 缓存命中率；先有账单才有预算。按租户出账的数据从哪来？→ 怎么降？高级篇 H.3/I.5、生产篇 6.5
提示注入文件、网页、命令输出都可能是注入源；防线是工具最小暴露 + 服务端授权 + 沙箱，不是“提示词求它别做”。为什么 project trust 不是安全边界？→ 你的沙箱方案？进阶篇 A.9/F.1-F.3
多租户隔离一人一会话 + 每次工具执行做行级授权；共享会话等于共享记忆，这是应用层 bug，不是提示词问题。怎么证明隔离生效？→ 凭据怎么按人注入？第 08 课、高级篇 I.2/I.3、生产篇 6.1
MCP把外部服务标准化成工具的协议；工具名有命名空间，来源要审查，暴露面要控制。SDK 会话里为什么工具不出现？→ deferred 暴露是什么？进阶篇 D.4、SDK 深入篇 02/04
检查点： 随机挑一行，合上页面把“一句话 + 追问链第一层”讲出声。讲不顺的行，回到落点重读——这就是这份教程每课“检查点”设计的意义。

求职篇 03 · 作品集

三个项目：从教程产物到简历条目

面试官平均看一份项目 90 秒，所以每个项目要有“一句简历话 + 三个可演示点 + 一个架构决策故事”。下面三个项目全部源自这套教程的产物，只差包装。

项目 A · 多租户 Agent 服务

生产篇 6.1–6.6 的完整产物：SSE 流式、按用户持久化、串行队列、trace/usage 落盘、容器交付。

简历句式：“基于 pi SDK 构建多用户流式 Agent 服务：JWT 认证、按用户会话持久化与恢复、忙时排队、断连自动取消，trace/成本按租户落盘，容器化交付。”

演示点：两窗口两用户互不可见；断连即停（trace 里 aborted: true）；SIGTERM 优雅退出日志。

决策故事：为什么 409 改排队、为什么同步占坑——讲“看起来空闲其实忙”的竞态与修复。

项目 B · 带审批的写操作 Agent

生产篇 6.4 + 自选扩展：把 create_ticket 换成真实业务（如订单退款、数据订正），加幂等键与失败补偿。

简历句式：“实现 human-in-the-loop 工具审批流：tool_call 挂起、SSE 推卡、超时 fail-closed；写操作幂等，失败可补偿。”

演示点：审批卡到执行的完整时序；超时自动拒绝；越权审批被 404 拒绝。

决策故事：为什么审批在扩展钩子而不是 subscribe 里做——观察通道与门控契约的源码级区别。

项目 C · MCP 工具服务器与受控接入

自己写一个 MCP 服务器（如公司内部知识库检索），接进 DataAgent，用暴露控制（deferred + tool_search）管理工具面。

简历句式：“开发内部知识库 MCP 服务器并接入 Agent：工具命名空间隔离、按需加载暴露控制、来源审查与最小权限清单。”

演示点：mcp__前缀工具的发现与调用；deferred 暴露前后 getActiveToolNames 对比。

决策故事：为什么检索做成工具而不是塞进系统提示词——上下文预算与按需加载的账（高级篇 G.2）。

仓库的门面： 三个项目一个 monorepo 就够。README 按架构决策记录（ADR）写：问题、选项、决策、验证结果。评测集挂 CI 的徽章放在最显眼的位置——“有评测门禁”是候选人信号里最稀缺的一个。

求职篇 04 · 答辩词

“为什么你学的是 pi，不是 LangChain？”

这道题几乎必来。标准答案有三层，全部是事实：

第一层，我学的是引擎不是框架。 我通读过 pi 的 agent loop、会话树、压缩和扩展系统的源码——run 和 turn 怎么终止、压缩为什么切在下一轮请求前、工具参数校验为什么在扩展钩子之前，这些是任何框架都绕不开的底层问题。换框架是换 API，不换原理。

第二层，pi 是最接近“生产引擎”的教材。 它是单进程单循环的设计，把多租户、凭据、限流、持久化全部留给我——这正是企业级工程师真正要写的那一层。LangChain 类框架替你做了太多决定，学它容易把“框架用户”误当“系统能力”。

第三层，概念我可以当天映射过去。 框架对照表（本册 01）就是证明：门控对应 interrupt，会话持久化对应 checkpointer，评测对应 evals。给我一周，我交付的是同一层抽象下的另一个实现。

自检问题合格标准

评测门禁在 CI 里真的红过吗？红过（故意改坏提示词录屏/截图）
能说出一次真实踩坑的源码级原因吗？能（推荐：409 竞态或缓存打穿）
框架对照表的左列能默写吗？12 行里至少 8 行
最后一句话： 这套教程从头到尾在训练同一件事——每一层负责什么、出问题去哪一层找。面试里最值钱的话不是“我用过 X”，而是“这个问题出在会话层，我用 trace 证明了它”。去把这句话变成你的。

学 Pi Agent 的目标不是背 API，而是知道每一层负责什么、出问题该去哪一层找。
