实战篇 · 多用户 Web Agent

这一章要造什么：一个能跑的 data-agent 服务

第 09 课给的是骨架，这一章给完整实现——零 Web 框架（Node 原生 http），只依赖 Pi SDK 和主线项目的 query_sales 工具。做完你将拥有：按用户隔离的会话、SSE 流式输出、工具状态推送、 断连自动取消、最小必要暴露。

功能清单

POST /chat 触发任务；SSE 实时回传文字增量与工具状态；同一用户忙时返回 409；客户端断开即取消运行。

故意不做的事

真实认证（用请求头模拟 userId）、持久化、限流——它们在升级路线与高级篇 I 的清单里，练习里做。

前置知识

主线项目的 src/tools/query-sales.ts；第 09 课 9.1 的排队语义；高级篇 K 的“delta 渲染、end 落库”规则。

实战篇 01 · 会话注册表

每用户一份会话：工厂 + 注册表

第 08 课的教训 + 第 09 课的工厂，合成一个可复用模块：一个 Map 管“userId → 会话”； ModelRuntime 全局共享一份——它只管模型与凭据，不承载对话状态。

src/sessions.ts · 用户会话注册表（完整代码）
import {
  createAgentSession,
  DefaultResourceLoader,
  getAgentDir,
  ModelRuntime,
  SessionManager,
  type AgentSession,
} from "@earendil-works/pi-coding-agent";
import { querySalesTool } from "./tools/query-sales.ts";

export type UserEntry = {
  session: AgentSession;
  running: boolean;
};

const sessions = new Map<string, Promise<UserEntry>>();

export async function initModelRuntime(): Promise<ModelRuntime> {
  const modelRuntime = await ModelRuntime.create();
  if ((await modelRuntime.getAvailable()).length === 0) {
    throw new Error("没有可用模型：请先配置 Provider 和 API Key");
  }
  return modelRuntime;
}

function createUserSession(userId: string, modelRuntime: ModelRuntime): Promise<UserEntry> {
  const loader = new DefaultResourceLoader({
    cwd: process.cwd(),
    agentDir: getAgentDir(),
    systemPromptOverride: () =>
      [
        `你是用户 ${userId} 的销售数据分析助手。`,
        "回答数字前必须先使用 query_sales 查询。",
        "不能编造数据；查询没有结果就明确说明。",
        "只回答当前提问用户的问题。",
      ].join("\n"),
    appendSystemPromptOverride: () => [],
  });

  return (async () => {
    await loader.reload();
    const model = (await modelRuntime.getAvailable())[0];
    const { session } = await createAgentSession({
      model,
      modelRuntime,
      resourceLoader: loader,
      customTools: [querySalesTool],
      tools: ["query_sales"],
      sessionManager: SessionManager.inMemory(),
    });

    const entry: UserEntry = { session, running: false };
    session.subscribe((event) => {
      // 同步维护运行标志：下一节的并发路由依赖它
      if (event.type === "agent_start") entry.running = true;
      if (event.type === "agent_settled") entry.running = false;
    });
    return entry;
  })();
}

/** 懒创建 + 去重：同一用户的并发首请求不会建两份会话 */
export function getOrCreate(userId: string, modelRuntime: ModelRuntime): Promise<UserEntry> {
  let entry = sessions.get(userId);
  if (!entry) {
    entry = createUserSession(userId, modelRuntime);
    sessions.set(userId, entry);
  }
  return entry;
}
三个设计决定： 注册表存 Promise 而不是结果——并发首请求天然去重； ModelRuntime 全局一份——凭据轮换只在它身上做一次（高级篇 I.3）； userId 进系统提示词——让隔离可观测，但真正的隔离靠“一人一会话”（第 08 课），提示词只是展示层。

实战篇 02 · HTTP 与 SSE

服务主体：一条白名单化的 SSE 管道

原生 http 就够，每一层都是前文机制的落地：认证占位 → 懒建会话 → 忙时 409 → 白名单事件流 → 断连取消。 八个编号步骤，对照第 09 课的骨架看。

src/server.ts · 完整服务（可直接运行）
import { createServer, type IncomingMessage, type ServerResponse } from "node:http";
import type { AgentSessionEvent } from "@earendil-works/pi-coding-agent";
import { getOrCreate, initModelRuntime } from "./sessions.ts";

function sseWrite(res: ServerResponse, payload: unknown): void {
  res.write(`data: ${JSON.stringify(payload)}\n\n`);
}

function readJson(req: IncomingMessage): Promise<{ message?: string }> {
  return new Promise((resolve, reject) => {
    let data = "";
    req.on("data", (chunk: Buffer) => {
      data += chunk;
      if (data.length > 100_000) reject(new Error("body too large"));
    });
    req.on("end", () => {
      try { resolve(JSON.parse(data || "{}")); } catch { reject(new Error("bad json")); }
    });
    req.on("error", reject);
  });
}

async function main(): Promise<void> {
  const modelRuntime = await initModelRuntime();

  const server = createServer(async (req, res) => {
    // ① 认证占位：真实项目换成认证中间件，从会话/令牌取 userId
    const userId = req.headers["x-user-id"];
    if (typeof userId !== "string" || userId.length === 0) {
      res.writeHead(401).end("missing x-user-id");
      return;
    }
    if (req.method !== "POST" || req.url !== "/chat") {
      res.writeHead(404).end();
      return;
    }

    // ② 输入校验：长度上限是最便宜的防线
    const body = await readJson(req);
    const message = body.message?.trim() ?? "";
    if (message.length === 0 || message.length > 4000) {
      res.writeHead(400).end("invalid message");
      return;
    }

    // ③ 懒建会话（并发安全，见实战篇 01）
    const user = await getOrCreate(userId, modelRuntime);

    // ④ 并发规则：同一用户同时只跑一个 run。这里必须“同步占坑”：
    // running 靠 agent_start 事件置位会有空窗（高级篇 J.1：看起来空闲其实忙），
    // 两个请求可能在第一个 agent_start 发出前先后通过检查。所以先同步置位，事件只做兜底。
    if (user.running) {
      res.writeHead(409).end(JSON.stringify({ error: "任务进行中，请稍候" }));
      return;
    }
    user.running = true;

    // ⑤ SSE 响应头
    res.writeHead(200, {
      "content-type": "text/event-stream",
      "cache-control": "no-cache",
      connection: "keep-alive",
    });

    // ⑥ 白名单转发：只暴露浏览器需要的字段（高级篇 K：delta 渲染，end 落库）
    let closed = false;
    const unsubscribe = user.session.subscribe((event: AgentSessionEvent) => {
      if (closed) return;
      switch (event.type) {
        case "message_update":
          if (event.assistantMessageEvent.type === "text_delta") {
            sseWrite(res, { type: "delta", delta: event.assistantMessageEvent.delta });
          }
          break;
        case "tool_execution_start":
          sseWrite(res, { type: "tool_start", toolName: event.toolName });
          break;
        case "tool_execution_end":
          sseWrite(res, { type: "tool_end", isError: event.isError });
          break;
        case "agent_settled":
          sseWrite(res, { type: "settled", aborted: event.aborted });
          break;
      }
    });

    // ⑦ 客户端断开：停止订阅 + 取消运行（第 09 课踩坑实验的修法）
    res.on("close", () => {
      if (closed) return;
      closed = true;
      unsubscribe();
      if (user.running) void user.session.abort();
    });

    // ⑧ 执行并收尾：final 用权威最终文本，不回传原始异常。
    // closed 已断开时不再写流；若 prompt 在进入 run 之前就被拒绝（没有事件兜底），
    // catch 里同步释放占坑，避免用户被永久 409。
    try {
      await user.session.prompt(message);
      if (!closed) sseWrite(res, { type: "final", text: user.session.getLastAssistantText() ?? "" });
    } catch {
      user.running = false;
      if (!closed) sseWrite(res, { type: "error", message: "服务暂时不可用，请稍后重试" });
    } finally {
      unsubscribe();
      if (!closed) res.end();
    }
  });

  server.listen(8787, () => console.log("listening on http://localhost:8787"));
}

main().catch((error) => {
  console.error(error);
  process.exit(1);
});
安全占位必须换掉： x-user-id 请求头只是教学占位——任何人都能伪装。真实部署里 userId 必须来自认证中间件 （会话令牌、JWT），并按高级篇 I.3 注入每用户凭据。这份代码的边界是“机制教学”，不是“可直接上线”。

实战篇 03 · 跑起来

验证：curl 先行，浏览器殿后

终端 · 启动与测试
node src/server.ts

# 另开一个终端：-N 关闭 curl 缓冲，观察 SSE 流
curl -N -H "x-user-id: alice" -H "content-type: application/json" -d "{\"message\":\"华东有哪些销售记录？\"}" http://localhost:8787/chat

# 换个用户名再试：会新建一份会话，历史互不可见
curl -N -H "x-user-id: bob" -H "content-type: application/json" -d "{\"message\":\"我叫小红。我叫什么名字？\"}" http://localhost:8787/chat

期望的 SSE 流（节选，每行一个事件）：

SSE 输出（节选）

data: {"type":"final","text":"华东地区共有两笔销售记录……"}

浏览器端用 fetch 读流——EventSource 只支持 GET，这里是 POST + ReadableStream：

浏览器测试片段
const res = await fetch("/chat", {
  method: "POST",
  headers: { "x-user-id": "alice", "content-type": "application/json" },
  body: JSON.stringify({ message: "华东有哪些销售记录？" }),
});
const reader = res.body!.pipeThrough(new TextDecoderStream()).getReader();
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  for (const chunk of value.split("\n\n")) {
    if (chunk.startsWith("data: ")) console.log(JSON.parse(chunk.slice(6)));
  }
}
练习 · 三个必须亲手制造的故障
  1. alice 的任务运行中，再发一个 alice 请求 → 观察 409。
  2. 任务运行中直接 Ctrl+C 关掉 curl → 在服务端确认 run 被 abort（settled 事件 aborted = true）。
  3. 用 alice 说“我叫小明”，再用 bob 问“我叫什么名字” → 隔离生效。

检查点：三个故障分别对应教程哪一课的哪个机制？

实战篇 04 · 升级路线

从“能跑”到“能上线”：按顺序补这五块

这五块现在已经不再是“留给你做”——每一块的完整实现都写成了第 6 册 生产篇 · 上线交付。做完那一册，你才第一次拥有可以写进简历的制品。

升级路线：每一块都有教程落点
顺序升级怎么做 / 落点
1忙时排队而不是 409把 409 分支换成 session.steer()（插话）或 followUp()（追加）；新连接同样订阅会话即可看到后续事件，等 agent_settled 再收尾（第 09 课 9.1）
2真实认证与凭据认证中间件换掉 x-user-id；按用户 setRuntimeApiKey（高级篇 I.3）
3会话持久化inMemory → 文件（sessionDir 按用户分目录）或自建存储，进程重启不丢历史（高级篇 I.2）
4观测与审计挂高级篇 H 的 trace 记录器，按 userId 落 JSONL；usage 进成本账
5边界与隔离容器部署（进阶篇 F）、工具服务端授权、限流与队列上限（高级篇 I.6 清单）
验收标准： 两个浏览器窗口、两个用户、同时提问、互不可见、断开即停、每条请求在 trace 里查得到—— 六个“是”，就是这门课的毕业线。

学 Pi Agent 的目标不是背 API，而是知道每一层负责什么、出问题该去哪一层找。
