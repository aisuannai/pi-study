# 《Pi Agent 入门实验室》审查报告

> 审查人立场：独立 Agent 架构师视角。审查标准只有三条：①以实战为出发点 ②以源码为主、文档为辅 ③成体系，能支撑"企业级 Agent 开发 + 找到工作"。
> 审查方法：五册全文精读 + 对 `@earendil-works/pi-coding-agent@1.6.1` 真实产物（dist / d.ts / sourcemap / 随包 docs / examples）逐项抽查核对。

## 一、总体结论

**这是一份事实准确性罕见的教程，但当前形态是"优秀的原理课"，还不是"完整的企业级实战课"。**

| 维度 | 评分 | 判断 |
|---|---|---|
| 事实准确性（源码核对） | 9.5 / 10 | 抽查 25+ 项断言，全部与 1.6.1 产物一致，含精确到标点的报错信息 |
| 教学设计 | 9 / 10 | 踩坑实验、责任边界图、按层排查表是明显高于市面水平的设计 |
| 实战覆盖 | 6 / 10 | 能跑通的"机制教学"有了；可部署、可写进简历的"交付物"没有 |
| 源码为主程度 | 7 / 10 | 摘录准确但占比低（约 6 处集中摘录）；缺一套"读源码方法论"的显式训练 |
| 体系化程度 | 6 / 10 | 单册内部结构极好；五册之间编号混乱、交叉引用断裂、无总纲依赖图 |
| 求职迁移性 | 5 / 10 | 全部绑定 pi API；与主流框架（LangGraph / Vercel AI SDK / OpenAI Agents SDK）无对照，无面试映射 |

一句话：**教程已经做到了"让你看懂一个生产级 Agent 引擎是怎么造的"，还没有做到"逼你交付一个生产级 Agent 系统"。** 前者是它的最大优点，后者是你目标的缺口，也是本报告的主体。

## 三、逐册点评

### index.html · 入门篇（最强的一册）
- 亮点：踩坑实验全是真问题（already processing、会话串台、忙等阻塞 _emit、abort 不生效），每课一条"主线项目"让 DataAgent 逐层生长，附录按层排查表可直接当运维手册。
- 问题：
  1. **第04课与毕业实战自相矛盾**：第04课说"生产代码不靠 `choices[0]` 碰运气"，但毕业实战代码和 `sessions.ts` 都用 `getAvailable()[0]`。教学线应该在这里完成"第04课的兑现"：`getModel("anthropic", "claude-opus-4-5")` + 明确报错。
  2. 第06课工具的教学数据是内存数组，**没有埋下"真实数据源（数据库/HTTP）"的替换接口**，导致后面所有隔离/权限论述停在原则层面（见第四节 P0-2）。

### cli.html · 进阶篇
- 亮点：A.5 三种输出模式对照、B.5 事件四种处理模式（通知/原地修改/链式转换/门控）是全教程抽象最好的两处，这两张表本身就是面试级知识。
- 问题：
  1. **渲染 bug**：A.7 末尾"见 SDK 深入篇 03。"和 D.4"见 SDK 深入篇 04。"各重复了 5 次（HTML 元素复制残留），必须修。
  2. F 章容器化讲的是"容器里跑 pi CLI"，而你的实战目标是"容器里跑自己写的 server"——两者是不同的 Dockerfile，现在缺后者（见第四节 P0-4）。

### advanced.html · 高级篇（含金量最高，但两处"说而不做"）
- 亮点：G 章通用概念对照表是"跳出 SDK"的正确动作；J/K 章源码深潜是全网少有的 pi 引擎逐行走读，J.5"截断即失败"这种细节直接来自源码，价值极高。
- 问题：
  1. **H.4 的 eval 代码跑不起来**：`runCase` 定义了但没有 main 循环、没有判定输出、没有通过率统计。评测是"企业级"的核心证据，示例必须可执行（改法见第四节 P0-3）。
  2. I 章企业级四道坎（多租户/凭据/可靠性/成本）全是"清单+一句机制"，**没有一处落到代码**。清单本身质量高，但与你的目标冲突：企业级恰恰不能只停留在清单。
  3. 编号混乱：本册章节标题写"进阶篇 G / 高级篇 H"，与册名"高级篇"冲突，五册交叉引用（"见进阶 B.4"）在这种命名下很容易指错册。

### sdk.html · SDK 深入篇
- 亮点：2.2 生效时机表（钩子构造即生效 vs `session_start` 要等 `bindExtensions`）是源码级干货，"忘了 bind 的典型症状"这种写法就是生产排查的样子。
- 问题：04 节 MCP 只演示"接上"，没有演示**暴露控制**（`exposure: deferred` + `tool_search` 按需加载只提了一句）。对企业场景，"哪些 MCP 工具对哪些用户可见"是权限问题，值得半页。

### web.html · 实战篇
- 亮点：零框架、白名单事件、断连取消、409 忙拒绝，"故意不做的事"明确划边界，这是正确的教学取舍；三个故障实验设计得好。
- 问题（3 个代码级缺陷，都可修）：
  1. **409 检查有竞态**：`running` 标志靠 `agent_start` 事件置位，而两个请求可以在第一个 `agent_start` 发出前先后通过 `if (user.running)` 检查（你自己高级篇 J.1 写过"看起来空闲其实忙的窗口真实存在"）。修法：取到会话后**同步**占坑——`if (user.running) return 409; user.running = true;` 再调 prompt，事件只用来清标志兜底。
  2. **`final` / `error` 写入未判 `closed`**：断连后 `sseWrite(res, …)` 仍会执行（subscribe 回调里判了，第⑧步没判）。Node 多数情况静默丢弃，但严谨做法是 `if (!closed) sseWrite(...)`。
  3. x-user-id 已声明"教学占位"没问题，但建议在代码注释处直接给出要替换成的中间件签名（`(req) => Promise<AuthUser>`），让"占位→真实"的替换路径可见。

## 四、以"企业级 + 求职"为标尺的差距（按优先级）

### P0 —— 不补上，学完仍拿不出企业级证据

1. **交付物断层**。实战篇"升级路线"五块（排队、真实认证、持久化、观测审计、容器边界）每一块都有"怎么做的落点"，但**没有一块有实现**。学完五册，你手里只有 `node src/server.ts` + x-user-id 的进程，没有任何可以写进简历的 artifact。企业级不是知识清单，是"可部署、可回滚、可审计"的制品。
2. **数据面只有只读**。DataAgent 全程内存数组，`execute` 里的"服务端授权"没有真实载体。企业面试必问的行级权限（userId 过滤）、写操作幂等、失败补偿，教程一个都没有。建议第二主线改成"带真实 SQLite 的工单/订单查询 + 写操作审批"，哪怕只有一个表。
3. **评测不可执行**。H.4 评测金字塔方向完全正确，但示例没有 runner：应补 `eval/run-eval.ts` 的 main（逐用例跑 → 输出 pass rate → 非 0 退出码），并给一条 GitHub Actions 片段。**"评测挂 CI"这件事本身做了，才叫企业级。**
4. **缺 Web 端 human-in-the-loop 审批流**。教程的人机协同停留在 CLI 的 `ctx.ui.confirm`。企业 Agent 最常见的形态是：模型要执行写操作 → 服务端挂起 → 推送审批卡到前端 → 用户批准/拒绝 → 恢复执行。pi 的机制基础教程都给齐了（`tool_call` block、`bindExtensions({ uiContext })`），缺的就是这条端到端线路。**这是五册与"企业级"之间最大的一块空白。**

### P1 —— 显著影响面试竞争力

5. **RAG / 知识库检索完全缺失**。企业 Agent 招聘需求里出现频率最高的词。教程的记忆一章讲的是"上下文工程"（讲得很好），但没有向量检索、召回、rerank 的位置。不必做完整 RAG 系统，但至少要有"把检索做成一个 pi 工具 + 评估检索质量"的一节，与 G.2 上下文预算打通。
6. **可观测性没有落进现有体系**。H.2 的自研 trace 雏形是对的，但"映射到 OTel"只有一句话。补一节：把 run/turn/tool 三种 span 通过 OTLP 导出（哪怕只打到 console exporter），企业面试聊 trace 上下文传播、span 属性时你才有实感。
7. **框架迁移对照缺失**。G.1 的"通用概念对照表"是正确起点，但只有 pi 一列。补一张四列对照表：通用概念 ↔ pi 实现 ↔ LangGraph 对应物 ↔ OpenAI Agents SDK / Vercel AI SDK 对应物。面试官不问 pi，问的是"你理解 agent loop 还是只会用某框架"——这张表就是你回答的弹药，也是"为什么学 pi"的答辩词。
8. **部署对象错了**。F 章的 Dockerfile 打包的是 pi CLI；你的 server 才应该被容器化（多阶段构建、非 root 用户、HEALTHCHECK、SIGTERM 优雅停机的完整代码）。I.4 的停机顺序写了，但没有可运行版本。

### P2 —— 锦上添花

9. 限流/排队的真实实现（队列上限、超时、公平性）。
10. 成本看板（usage 聚合到 SQLite，按 userId/租户出报表）——H 章有数据来源，差一步聚合实现。
11. 提示注入红队练习：把 OWASP LLM Top 10 映射到 F 章威胁列表，做 2 个注入实验（AGENTS.md 夹带指令 → 工具参数注入）。

## 结语

你这套教程的最优资产是**事实准确 + 责任边界意识**（"提示词不是权限系统"、"隔离与并发是一体两面"、"审计不踩时序坑"），这在 AI 生成教程泛滥的环境里几乎独一份。它当前的结构性短板只有一个：**从头到尾都在教你理解 pi，而没有逼你交付一个不依赖 pi 也能自证的系统**。补上第 6、7 册，这套教程就从"极好的学习笔记"变成"企业级 Agent 工程师的训练体系"。
